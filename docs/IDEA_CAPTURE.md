# Ideen erfassen

Für den Projekt-Chat, das Handy oder eine eigene Ideen-Session. Umgesetzt wird nur in der umsetzenden Session (siehe [`DEVELOPMENT_WORKFLOW.md`](DEVELOPMENT_WORKFLOW.md)).

## Erlaubt
- Neues Issue in `mgritsch04/fitness-coach`, Titel `[IDEE] …`, Label **`idea-inbox`** (optional ein Bereichslabel wie `area: coach`).
- Offene `idea-inbox`-Issues per Kommentar ergänzen; vorher nach ähnlichen Issues suchen.

## Nicht erlaubt
Dateien ändern, Branches/PRs anlegen, `docs/IDEAS.md` bearbeiten, Labels anderer Issues ändern, Issues schließen, User-Tests beantworten (das machst du selbst mit `BESTANDEN` / `FEHLGESCHLAGEN: …`).

## Inhalt eines Ideen-Issues
**Was soll besser werden?** · **Warum / wofür?** · optional **Woran merke ich, dass es fertig ist?** und Dringlichkeit (hoch/mittel/niedrig).

## Vorlage für eine Ideen-Session
> Du hilfst mir nur beim Erfassen von Ideen für `mgritsch04/fitness-coach`. Lege für jede Idee ein GitHub-Issue „[IDEE] …“ mit Label `idea-inbox` an (Abschnitte: Was soll besser werden? / Warum? / Woran merke ich, dass es fertig ist? / Dringlichkeit). Suche vorher nach ähnlichen offenen Issues und ergänze dort per Kommentar. Ändere keine Dateien, Branches, PRs oder Labels anderer Issues und schließe keine Issues. Schreibe nie Gesundheitsdaten oder Zugangsdaten in Issues. Antworte auf Deutsch.
